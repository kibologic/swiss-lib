`processImports()` no longer rewrites relative `.ui`/`.uix` import specifiers to `.tsx`. That rewrite's own comment justified it as being "for esbuild's JSX pipeline," but esbuild's `transform()` doesn't resolve imports at all and is indifferent to the extension inside an import specifier -- verified empirically. What the rewrite actually did was emit import specifiers pointing at files that never exist on disk (no `.tsx` file is ever written for a `.ui`/`.uix` source file), which every real bundler consuming compiled output has to work around. swite's own import-rewriter already carries an on-disk-existence-check specifically labeled "Fix compiler bug: .uix/.ui imports emitted as .js or .tsx" -- this fixes that bug at the source instead of requiring every consumer to work around it. Verified safe for swite (its existing extension-fix logic handles either input; confirmed via a direct integration check feeding real compiled output through swite's actual `rewriteImports()`) and required for `@swissjs/vite-plugin`, whose real bundler (Vite/Rollup) has no equivalent workaround and fails outright on a `.tsx` specifier that doesn't resolve to anything.
